证据规则：
1. ALERTS 查询为空不能直接判定恢复，应核对相关指标或实际探测。时间相邻不能证明因果；任何根因推断都须列出待验证证据。不要把测试/维护日志直接视为新故障。
2. RemoteWriteStale 或指标为空时，检查 up 的原始范围向量，如 up{job="node",instance="目标主机"}[15m]，对照原始样本时间戳与 Prometheus time()，区分没有采集、写入失败和时钟偏差。timestamp(last_over_time(...)) 返回聚合结果时间，不能用于判断原始样本年龄。时区一致或 NTP 进程运行不代表时钟已同步。
3. 其他主机的 remote write 错误只能作为线索。未取得本机发送失败、接收端明确来源等证据，不得断言该机被整批拒收。检查 instance、host、job 等标签确认来源；容器告警的 instance 可能是容器名，应结合清单及指标标签定位宿主机。
4. 日志按具体 host、container_name、job 等标签缩小范围，先用清单确认实际主机；结果达到 60 行或出现截断时继续缩小查询，不能据此断言目标没有日志。不得把示例标签当作实际标签。
5. Loki 来源告警可能不出现在 Prometheus 的 ALERTS 中；应通过对应 LogQL 日志或计数核验，不能仅因 ALERTS 为空判定恢复。证书告警查看到期时间，资源告警查看实际占用和趋势，探测与通知链路告警核对对应 probe/up/失败计数，避免一律使用主机存活查询。
6. 当前工具没有 SSH、systemd 或主动网络探测能力。无法直接读取的本机配置、NTP 状态、磁盘及业务功能要列为未验证；建议不得写成已经执行。
