> 回答一个问题：**如果今天某块盘或 PVE 宿主机坏了，Homelab 能恢复到什么程度？**
> 现状：2026-11-03 PVE 导出确认**没有备份任务**；各服务无单独备份沿用既有记录，本次未重新审计。2026-10-07 决定暂不做备份，本文只评估现状、记录风险，不是备份方案。
> 数据位置、大小、是否在 Git 的依据仍是 2026-10-07 实际采集。2026-11-03 PVE 导出更新为 10 台运行中 VM，Windows10、archvm 已开机，旧 hybin 的 VMID 107 已复用于 k8s-master，另有 108、109 两台 Kubernetes 节点；新增节点的磁盘归属与数据资产尚未盘点。服务列表见 [[03-服务清单]]，机器见 [[01-主机清单]]。
> 已确认新增 WireGuard（ECS + bastion），手机内网与代理访问可用；Orca 尚未安装。本次未运行采集脚本，未重新检查备份任务或数据大小。

## 结论

1. **能恢复的只有 GitHub 上的东西**：知识库（`hybinlab/obsidian-vault`）、pveui 代码（`LSPHYB/pveui`），以及 MoneyPrinterTurbo、calibre-web、CloudBeaver 这类上游开源项目的代码。
2. **所有自己写的配置都只存在于 VM 磁盘上**，不在 Git 里：监控告警栈、Caddy、Ansible playbook、主机清单生成器、frpc、各服务 compose 文件、SSH 密钥。
3. **真正不可替代的数据很少**：不算媒体文件，加起来不到 1G（Vaultwarden 只有 2M）。
4. 知识库里的 SOP 和 `homelab/services/` 运维手册记录了大部分配置（监控、ntfy、Alloy、ECS/frp、Caddy 及核心服务），**丢了能照着文档重建**；还没有文档的主要是 Ansible、code-server、Samba，以及所有密钥。
5. **最大的已知存储单点是 sdd**：2026-10-07 核实的既有 VM 系统盘（qcow2）集中在这一块 1TB SSD 上，它损坏会使其上的配置和数据丢失。当前 VM 总数为 10，新增 Kubernetes 节点的盘归属待核实，不能仅凭资源清单断言全部 10 台都在 sdd。
6. 媒体盘 sdb、sdc 是直通给 docker-host 的独立物理盘（2.5 寸机械盘），不受 sdd 影响；其中 **sdb 有一片已知坏块**（已处理，见 [[磁盘坏道排查与修复记录]]）。

## 故障场景

| 场景 | 后果 | 能否恢复 |
|---|---|---|
| 单个容器 / 服务挂了 | 只影响该服务 | ✅ 重启或按 compose 重建（compose 文件还在盘上） |
| 误删文件 / 误操作 / 被入侵加密 | 对应数据丢失 | ❌ 没有任何历史版本可回滚 |
| 某台 VM 系统盘损坏 | 该 VM 上的配置和数据全部丢失 | ❌ 只能照知识库重建，数据丢失 |
| **docker-host 系统盘损坏** | 约 25 个服务的配置 + Vaultwarden、Karakeep、Grafana、监控配置全部丢失；告警系统本身也没了 | ❌ 影响最大的单点 |
| PVE 系统盘 sda 损坏 | PVE 和 `/etc/pve` 里的 VM 定义丢失；VM 磁盘在 sdd 上，还在 | ⚠️ 重装 PVE → 挂载 sdd 到 `/mnt/vm-images` 并重新添加存储 → 按 [[01-主机清单]] 的 VMID/配置手工重建 VM、挂回 qcow2 和直通盘 |
| **sdd（vm-images）损坏** | 存放于此的 VM 系统盘丢失，涉及既有核心配置和数据；新增 Kubernetes 节点是否同属此故障域待核实 | ❌ 该盘数据没有已知备份；GitHub、知识库和独立媒体盘（sdb、sdc）可用于部分重建 |
| sdb 损坏（有已知坏块） | Jellyfin 媒体库（约 431G）丢失；Jellyfin 配置在系统盘上不受影响 | ❌ 除非媒体能从别处重新获取 |
| sdc 损坏 | OpenList 挂载的数据（约 443G，NTFS）丢失 | ❌ 同上 |

## 如果真的发生：恢复顺序

1. PVE（重装或修复）→ 确认 sdd（vm-images）、sdb、sdc 哪些还在
2. OpenWrt 不在 PVE 上，不随 PVE 故障停机；确认 31.11 网关、DNS、OpenClash 以及上级网关 192.168.1.1 正常
3. **docker-host**：Docker → Caddy → 监控告警栈（先恢复"能看见问题"的能力）→ 其他服务按 [[03-服务清单]] 的重要性顺序
4. **database**：MySQL、PostgreSQL（数据丢了的话应用要重新初始化）
5. **bastion**：frpc（Web 公网入口和相关告警访问）及 WireGuard 家庭端；异地恢复时还需确认 ECS 的 WireGuard 和 UDP 51820 可用，再验证内网与代理出口
6. **agent**：Ansible 环境（之后其他 VM 的 Alloy 等可以用 playbook 批量恢复）
7. middleware、实验机最后

如果 WireGuard 私钥无法恢复，重新生成相应设备的密钥并更新所有对端保存的公钥，撤销旧授权后再验收。不要从聊天记录或 Git 中寻找、恢复真实密钥值。
