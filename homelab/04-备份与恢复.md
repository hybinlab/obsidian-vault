> 回答一个问题：**如果今天某块盘或 PVE 宿主机坏了，Homelab 能恢复到什么程度？**
> 现状：**没有任何备份**。2026-10-07 决定暂不做备份，本文只评估现状、记录风险，不是备份方案。
> 依据：2026-10-07 在各 VM 上实际采集（数据位置、大小、是否在 Git），服务列表见 [[03-服务清单]]，机器见 [[01-主机清单]]。

## 结论

1. **能恢复的只有 GitHub 上的东西**：知识库（`hybinlab/obsidian-vault`）、pveui 代码（`LSPHYB/pveui`），以及 MoneyPrinterTurbo、calibre-web、CloudBeaver 这类上游开源项目的代码。
2. **所有自己写的配置都只存在于 VM 磁盘上**，不在 Git 里：监控告警栈、Caddy、Ansible playbook、主机清单生成器、frpc、各服务 compose 文件、SSH 密钥。
3. **真正不可替代的数据很少**：不算媒体文件，加起来不到 1G（Vaultwarden 只有 2M）。
4. 知识库里的 SOP 和 `homelab/services/` 运维手册记录了大部分配置（监控、ntfy、Alloy、ECS/frp、Caddy 及核心服务），**丢了能照着文档重建**；还没有文档的主要是 Ansible、code-server、Samba，以及所有密钥。
5. **最大的单点是 sdd**：8 台 VM 的系统盘（qcow2）全部放在这一块 1TB SSD 上，它坏了 = 几乎全部配置和数据丢失。
6. 媒体盘 sdb、sdc 是直通给 docker-host 的独立物理盘（2.5 寸机械盘），不受 sdd 影响；其中 **sdb 已有坏道迹象**。

## 磁盘与故障域（2026-10-07 在 PVE 上确认）

| PVE 磁盘 | 型号 | 大小 | 用途 | 坏了影响什么 |
|---|---|---|---|---|
| sda | Samsung MZNLF128HCHP（M.2 SATA SSD） | 128G | PVE 系统（`pve-root` 32G、swap 8G）、`local` 存储 | PVE 本身和 `/etc/pve` 里的 VM 定义 |
| **sdd** | HEORIADY HX-001（SSD） | 1TB | **`vm-images` 存储（`/mnt/vm-images`）：全部 VM 系统盘 qcow2，已用 307G** | **全部 VM** |
| sdb | WD WD10JPVX（2.5 寸 5400 转机械盘） | 1TB | 直通 docker-host（`scsi2`）→ `/mnt/jellyfin`，ext4 | Jellyfin 媒体库 |
| sdc | HGST HTS721075A9E630（2.5 寸机械盘） | 750G | 直通 docker-host（`scsi3`）→ `/mnt/openlist`，NTFS | OpenList 挂载的数据 |

> `vm-images` 存储的 content 里包含 `backup`，`prune-backups keep-all=1`，但没有任何备份任务，所以里面没有备份。即使将来在这里做 vzdump，备份和 VM 在同一块 sdd 上，sdd 坏了也一起丢。

## 故障场景

| 场景 | 后果 | 能否恢复 |
|---|---|---|
| 单个容器 / 服务挂了 | 只影响该服务 | ✅ 重启或按 compose 重建（compose 文件还在盘上） |
| 误删文件 / 误操作 / 被入侵加密 | 对应数据丢失 | ❌ 没有任何历史版本可回滚 |
| 某台 VM 系统盘损坏 | 该 VM 上的配置和数据全部丢失 | ❌ 只能照知识库重建，数据丢失 |
| **docker-host 系统盘损坏** | 约 25 个服务的配置 + Vaultwarden、Karakeep、Grafana、监控配置全部丢失；告警系统本身也没了 | ❌ 影响最大的单点 |
| PVE 系统盘 sda 损坏 | PVE 和 `/etc/pve` 里的 VM 定义丢失；VM 磁盘在 sdd 上，还在 | ⚠️ 重装 PVE → 挂载 sdd 到 `/mnt/vm-images` 并重新添加存储 → 按 [[01-主机清单]] 的 VMID/配置手工重建 VM、挂回 qcow2 和直通盘 |
| **sdd（vm-images）损坏** | 全部 8 台 VM 的系统盘丢失 = 几乎全部配置和数据丢失 | ❌ 只剩 GitHub、知识库和媒体盘（sdb、sdc） |
| sdb 损坏（已有坏道迹象） | Jellyfin 媒体库（约 431G）丢失；Jellyfin 配置在系统盘上不受影响 | ❌ 除非媒体能从别处重新获取 |
| sdc 损坏 | OpenList 挂载的数据（约 443G，NTFS）丢失 | ❌ 同上 |

## 如果真的发生：恢复顺序

1. PVE（重装或修复）→ 确认 sdd（vm-images）、sdb、sdc 哪些还在
2. OpenWrt 旁路由不在 PVE 上，不受影响；确认 31.11 网关和 DNS 正常
3. **docker-host**：Docker → Caddy → 监控告警栈（先恢复"能看见问题"的能力）→ 其他服务按 [[03-服务清单]] 的重要性顺序
4. **database**：MySQL、PostgreSQL（数据丢了的话应用要重新初始化）
5. **bastion**：frpc（公网入口和手机告警依赖它）
6. **agent**：Ansible 环境（之后其他 VM 的 Alloy 等可以用 playbook 批量恢复）
7. middleware、实验机最后
