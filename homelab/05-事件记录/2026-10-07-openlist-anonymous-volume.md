| 项目 | 内容 |
|---|---|
| 时间 | 部署时（2026-07）埋下 → 2026-10-07 约 22:10 发现 → 22:23 修复 |
| 现象 | 无（潜在隐患）。写 OpenList 运维手册时发现 compose 挂载的 `./data` 是空的，容器却挂着一个 1.7M 的匿名卷 |
| 影响 | 尚未发生。一旦执行 `docker compose down` 再 `up`，会换成新的空卷，**管理员账号和所有存储挂载配置全部丢失** |
| 根因 | 镜像的数据目录是 `/opt/openlist/data`，compose 却挂到了 `/root/openlist/data`（AList 时代的旧路径）。真正的数据落在 Docker 自动创建的匿名卷里；平时 `up -d` 重建会沿用旧匿名卷，所以一直没暴露 |
| 处理 | `docker cp` 拷出数据 → compose 改为 `./data:/opt/openlist/data` → 重建 → 删除旧匿名卷 |
| 验证 | 拷出的 `data.db` 与原卷校验和一致；重建后 2 个用户、1 个存储挂载都在，日志没有"新建管理员" |
| 后续措施 | - [x] [[OpenList]] 运维手册记录判断方法 ✅ 2026-10-07<br>- [ ] 服务清单生成器可以加一项检查：容器挂着匿名卷（名字是哈希）就提示 |

**经验**：`docker inspect` 里出现名字是一长串哈希的 volume，通常就是 compose 挂载路径和镜像声明的数据目录不一致。
