| 项目 | 内容 |
|---|---|
| 时间 | 开始时间未知（自 frp 代理配置以来）→ 2026-10-07 约 21:40 发现 → 当晚关闭 |
| 现象 | 从外网直接访问 ECS 公网 IP 的 `6989`、`5244` 端口返回 HTTP 200 |
| 影响 | **nexterm（网页 SSH 管理）** 和 **OpenList** 绕过 nginx 的 HTTPS，以明文 HTTP 直接暴露在公网：登录凭据明文传输，且容易被端口扫描发现。nexterm 能登录内网服务器 |
| 根因 | frp 的 `remotePort` 在 ECS 上监听 0.0.0.0，而 ECS 安全组放行了这两个端口。正确做法是 frp 远端端口只给本机 nginx 用，安全组只开 443 |
| 怎么发现的 | 做 Homelab 现状盘点时，从 frpc 配置里列出所有远端端口，逐个从外网探测 |
| 处理 | 在 ECS 安全组里关闭 6989、5244 |
| 验证 | 从外网再次访问两个端口均不通 |
| 后续措施 | - [ ] 修改 nexterm、OpenList 的登录密码（暴露期间无法确认是否被扫描过：经 frp 的访问在服务端看来都来自本机，日志里分辨不出公网来源）<br>- [ ] 考虑用 blackbox 定期从外部探测所有 frp 远端端口，有任何一个能直接访问就告警 |
