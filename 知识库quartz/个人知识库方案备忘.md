> 结论:**Obsidian(本地)+ Git(同步/版本)+ Quartz(展示)**,一个 vault、一个站。 Outline 出局,Perlite 不引入,Astro 博客并入 Quartz。

## 最终架构

```
┌─ 私有仓库 obsidian-vault ──────────────┐
│  全部笔记(含日记等私密内容)          │
│  PC: Obsidian Git 插件自动 commit/push │
│  手机: Syncthing 同步(手机不跑 git)  │
└──────────────┬─────────────────────────┘
               │ push 触发 repository_dispatch
               ▼
┌─ 公开仓库 quartz-site(Quartz v5)─────┐
│  GitHub Actions:                       │
│   1. checkout 自身                     │
│   2. checkout vault → content/(deploy key)│
│   3. rm -rf 私密目录(硬删)          │
│   4. npx quartz plugin install --from-config │
│   5. npx quartz build → 部署 Pages     │
└──────────────┬─────────────────────────┘
               ▼
   GitHub Pages(可绑自定义域名)
```

可选:PVE 上定时全量构建(不删私密),产物挂 Nginx = 内网完整版。

## 决策记录(为什么不用 X)

| 方案 | 结论 | 原因 |
|----|----|----|
| Outline | 不用 | 面向团队;自托管要 Postgres+Redis;与 vault 双数据源要自写同步脚本;"随时随地网页记录"被 GitHub 网页端/github.dev 覆盖 |
| Perlite | 不用 | 内网实时渲染是唯一优势,但成熟度低;用 Quartz 本地全量构建替代,全站单一技术栈 |
| MkDocs | 不用 | wikilink/callout 靠插件拼,兼容碎 |
| Astro 博客 | 归档合并 | 博客与笔记内容同质,都是展示;维护两套生成器不值。老文章 URL 用 Quartz frontmatter `aliases` 做跳转(如在意存量收录) |
| Obsidian Publish | 不用 | $8/月,自建免费能达到 |

⚠️ Quartz 的 GitHub Releases 停在 2023 v4——**这不代表停更**,作者不发 release,看 commit 历史(v5 分支持续活跃)。

## vault 目录与发布策略

```
obsidian-vault/
├── 00-inbox/          # 速记 → 不发布
├── 10-tech/           # 技术/学习/教程/排错 → 主要公开区
├── 20-work/           # 工作 → 永不发布
├── 30-journal/        # 日记 → 永不发布(硬隔离)
├── 40-posts/          # 原博客文章迁入
└── 90-attachments/    # 附件(敏感图片放 private/ 子目录)
```

双层保险:


1. **白名单为主**:`ExplicitPublish` filter,frontmatter 写 `publish: true` 才发布(默认不发,手滑只是漏发不泄密)
2. **目录硬删兜底**:CI 里 `rm -rf content/20-work content/30-journal content/00-inbox content/90-attachments/private`——日记类不依赖 filter,防配置改坏

`.gitignore`:`.obsidian/workspace.json`、`workspace-mobile.json`、`.trash/`

## Quartz 关键配置

* 要求 **Node ≥ v22**
* `quartz.config.ts`:`locale: "zh-CN"`(界面汉化)、`pageTitle`、`baseUrl`(无协议无尾斜杠)
* v5 新增步骤:`npx quartz plugin install --from-config`(CI 里也要加)
* 自定义收敛在 config / layout / `custom.scss`,**别动 quartz/ 核心**,否则升级冲突
* wikilink 坑:vault 内文件名保持全局唯一,重名会解析错

## 实施顺序


1. vault 建目录结构 + .gitignore,推 GitHub 私有仓
2. `git clone quartz` → `npx quartz create`,本地软链 vault 进 content,`npx quartz build --serve` 验证
3. 配 locale / baseUrl / ExplicitPublish,挑几篇打 `publish: true` 测过滤
4. 写 CI(私有仓 checkout 用只读 deploy key),跑通 Pages 部署
5. vault 侧加 push → repository_dispatch 触发
6. 迁 Astro 博客文章进 `40-posts/`,配 aliases,归档 Astro 仓库
7. (可选)自定义域名 / 手机 Syncthing / PVE 内网完整版

## 场景速查

* **外面只有浏览器想记一条** → GitHub 网页端改私有仓,或按 `.` 进 github.dev,丢 `00-inbox/`,回家 pull 整理
* **上线前自检** → 搜一遍构建产物确认无私密内容
* **迁存量日记** → 直接落 `30-journal/`,不要"先丢根目录再整理"
