## 故障概述

* **时间**: 2026-08-11
* **环境**: PVE 宿主机（E5-2699 v3）→ USB 外接硬盘盒 → WD 蓝盘
* **受影响 VM**: docker-host（Ubuntu 24.04.4）
* **症状**: VM 控制台出现 I/O error，.NET 进程阻塞超过 122 秒

## 硬件信息

| 项目 | 详情 |
|----|----|
| 磁盘型号 | WDC WD10JPVX-08JC3T6（WD Blue Mobile） |
| 容量 | 1 TB |
| 转速 | 5400 rpm |
| 接口 | SATA 3.0，通过 USB 硬盘盒接入 |
| 实际协商速率 | USB 2.0（480Mbps） |
| 通电时间 | 2990 小时 |
| 分区用途 | ext4，label `media`，直通给 docker-host VM |
| 挂载点 | `/mnt/jellyfin` |

## 故障现象

### VM 层（docker-host）

```
[66357.892527] INFO: task .NET TP Worker:212253 blocked for more than 122 seconds.
[66434.278045] I/O error, dev sdc, sector 1470487 op 0x0:(READ)
[239386.316092] I/O error, dev sdc, sector 1470815 op 0x0:(READ)
```

### 宿主机层（PVE）

```
[66426.837825] I/O error, dev sdd, sector 1471207 op 0x0:(READ)
[239378.736937] I/O error, dev sdd, sector 1471295 op 0x0:(READ)
```

同时伴随 USB 控制器反复 reset：

```
[354193.512787] usb 3-10: reset high-speed USB device number 2 using xhci_hcd
```

## 排查过程

### 1. VM 内 SMART 检查

VM 内 `/dev/sdc` 为 QEMU 虚拟磁盘，不支持 SMART，无法获取健康信息。需到宿主机排查。

### 2. 宿主机 SMART 检查

```bash

smartctl -a /dev/sdd
```

关键指标：

| 属性 | 值 | 说明 |
|----|----|----|
| Reallocated_Sector_Ct | 0 | 无已重映射扇区 |
| Current_Pending_Sector | **1** | 1 个扇区等待重映射 |
| Offline_Uncorrectable | 0 | — |
| SMART overall-health | PASSED | 整体判定通过 |

### 3. Short Self-Test

```bash

smartctl -t short /dev/sdd
```

测试完成后日志为空（`No self-tests have been logged`），原因为 USB 桥接芯片不支持 SMART 日志记录。

### 4. 坏道扫描（badblocks）

```bash

badblocks -sv -b 512 /dev/sdd 1473000 1471000
```

发现连续坏扇区：

| 坏扇区号 | 状态 |
|----|----|
| 1471207 | dmesg 报错 |
| 1471295 | dmesg 报错 |
| 1471425 | badblocks 发现 |
| 1471426 | badblocks 发现 |
| 1471427 | badblocks 发现 |
| 1471428 | badblocks 发现 |

每个坏扇区读取超时约 200 秒。

## 修复操作

### 1. 写零尝试触发重映射

```bash

dd if=/dev/zero of=/dev/sdd bs=512 count=1 seek=1471207 conv=notrunc

dd if=/dev/zero of=/dev/sdd bs=512 count=1 seek=1471295 conv=notrunc
```

写入成功，但 `Current_Pending_Sector` 未清零——USB 桥接芯片无法将重映射命令透传至磁盘固件。

### 2. 坏块号换算

分区起始扇区为 63，ext4 block size 为 4096（= 8 × 512），换算公式：

```
fs_block = (disk_sector - 63) / 8
```

| 磁盘扇区 | ext4 block |
|----|----|
| 1471207 | 183893 |
| 1471295 | 183904 |
| 1471425–1471428 | 183920（同一个 block） |

### 3. 标记 ext4 坏块

```bash

echo -e "183893\n183904\n183920" > /tmp/badblocks.txt

e2fsck -l /tmp/badblocks.txt /dev/sdd1
```

执行结果：

* 发现 1 个 mp4 文件的 3 个 block 与坏块重叠（inode ）
* 选择 clone 将数据复制到新块，原坏块标记进坏块表
* 文件系统修复完成，`e2fsck` 通过

### 4. 文件系统修复输出

```
media: Updating bad block inode.
Pass 1: Checking inodes, blocks, and sizes

Multiply-claimed block(s) in inode 12: 183893 183904 183920

Clone multiply-claimed blocks? yes

media: ***** FILE SYSTEM WAS MODIFIED *****
media: 677/61054976 files (1.6% non-contiguous), 104416709/244190000 blocks
```

## 遗留问题

| 问题 | 原因 | 影响 |
|----|----|----|
| `Current_Pending_Sector` 仍为 1 | USB 桥接无法透传重映射命令 | 无法由固件自动修复，需接 SATA 处理（2026-10-07 已处理，见下节） |
| USB 控制器反复 reset | 硬盘盒/数据线仅 USB 2.0 | 长时间 I/O 不稳定，传输速率低（\~6 MB/s）（已改 SATA 直连） |
| 受损 mp4 文件 | 3 个 4K block（12KB）数据丢失 | 播放时可能有极短暂花屏，需重新拷贝片源（2026-10-08 已删除） |

## 2026-10-07 后续：改 SATA 直连后再次处理

### 现象

坏块标记后，docker-host 仍然每隔约两天报一次读错误，30 天内 42 次，**全部是同一个扇区**：

```
I/O error, dev sdb, sector 1471431 op 0x0:(READ)
Sense Key : Aborted Command [current]
```

Loki 日志告警 DiskIOError 上线后才被注意到，事件记录见 [[2026-10-07-sdb-bad-sector]]。

### 根因：坏块只标了一半

盘已改为 SATA 直连（smartctl 显示 `SATA 3.0, 6.0 Gb/s (current: 6.0 Gb/s)`，SMART 和自检日志都能完整读取），盘符变成 PVE 上的 `sdb`，在 docker-host 里也是 `sdb`。

这块盘是 **512 逻辑 / 4096 物理** 扇区，而分区从 63 扇区开始，**没有 4K 对齐**。一个 4K 物理扇区会横跨两个 ext4 block：

```
物理扇区（4K 对齐）:      LBA 1471424 ─────────────── 1471431
ext4 block 183920:   1471423 ──────────────── 1471430            ← 上次已标坏块
ext4 block 183921:                                 1471431 ── 1471438   ← 漏了，仍属于 inode 12
```

上次 badblocks 找到的 1471425–1471428 和这次的 1471431 是**同一个物理扇区**，也就是 SMART 里那 1 个 `Current_Pending_Sector`。上次只把 block 183920 标进坏块表，183921 仍在那个 mp4 文件里，Jellyfin 定时扫描读到就报错。

反查方法（在 VM 内，文件系统挂载中也可以只读执行）：

```bash
# 扇区 → ext4 block → inode → 文件名
B=$(( (1471431 - 63) / 8 ))            # 分区起始 63，block 4K
debugfs -R "icheck $B" /dev/sdb1       # 得到 inode
debugfs -R "ncheck <inode>" /dev/sdb1  # 得到文件路径
dumpe2fs -b /dev/sdb1                  # 查看 ext4 坏块表
```

### 处理

SATA 直连后写入可以直达固件，按**整个 4K 物理扇区**写零（只写 512 字节会触发读-改-写，读不出来就失败）：

```bash
# docker-host：停 Jellyfin、卸载
cd /root/jellyfin && docker compose stop && umount /mnt/jellyfin

# PVE：用 by-id 防止写错盘；1471424 / 8 = 183928
D=/dev/disk/by-id/ata-WDC_WD10JPVX-08JC3T6_WD-WX21A66LKJCJ
dd if=/dev/zero of=$D bs=4096 count=1 seek=183928 oflag=direct conv=notrunc
dd if=$D of=/dev/null bs=4096 count=1 skip=183928 iflag=direct && echo READ_OK
smartctl -A $D | grep -E 'Reallocated_Sector|Current_Pending|Offline_Unc'

# docker-host：检查并恢复
e2fsck -f -n /dev/sdb1 && mount /mnt/jellyfin && cd /root/jellyfin && docker compose start
```

结果：读回成功，`Current_Pending_Sector` 1 → 0，`Reallocated_Sector_Ct` 仍为 0（固件判断写后可用，没有重映射）；`e2fsck` 无错误。

### 又发现一片坏块

完整读取那个 mp4 验证时，在扇区 1473871 又报错。在 PVE 上对附近做只读扫描（`-b 4096` 时块号就是 4K 物理扇区号，可直接作为 `dd` 的 `seek`）：

```bash
badblocks -sv -b 4096 $D 250000 150000   # 参数：最后一块 第一块
```

结果：100000 个块（约 400MB）中 **15 个坏块**，全部集中在 184233–196319（约 47MB 范围），大致每隔约 306 块（1.2MB）一个，前后其余区域没有坏块。上次只扫了 1471000–1473000 这一小段，所以这片坏块很可能早就存在，并不能说明在扩散。

坏块基本都落在那个 mp4 文件上，处理方式：**删除该文件**，不再逐个修复。

### 当前状态（2026-10-08）

| 项目 | 状态 |
|----|----|
| 受损 mp4 | 已删除（配图保留，重新下载同名文件可直接用） |
| 已知坏块区 | 184233–196319（4K 块号），现为空闲空间；以后新文件写到这里时，固件会重映射，也可能出现写错误 |
| 全盘扫描 | 未做，盘的其余部分情况未知 |
| SMART 整体 | PASSED；通电 4244 小时，30℃，UDMA CRC 0 |

## 后续建议


1. ~~**接 SATA**~~ — 已改为 SATA 直连
2. **定期监控** — 关注 `Current_Pending_Sector` 和 `Reallocated_Sector_Ct` 是否增长；几个月不动就可以继续当媒体盘用。新的读错误会由 DiskIOError 告警推送
3. **数据定位** — 该盘仅存放可替代的媒体文件，不存放重要数据
4. **换盘规划** — 5400rpm 笔记本蓝盘不适合作为服务器存储，后续可更换为 3.5 寸桌面盘或 SSD

5. **新盘注意 4K 对齐** — 分区起始扇区用 2048（`fdisk`/`parted` 默认值），避免一个物理扇区横跨两个文件系统块
