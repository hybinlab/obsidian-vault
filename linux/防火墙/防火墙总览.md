## 1. 架构关系

![[linux/防火墙/防火墙架构.canvas]]

- 2026 年主流发行版底层都是 **nftables**，iptables 命令实际是兼容层（`iptables -V` 可确认）
- 判断后端：输出含 `(nf_tables)` = nftables 后端，`(legacy)` = 传统 iptables

分工具详情：

- [[linux/防火墙/iptables.md|iptables]] — 五条链、四种动作、匹配机制、常用命令与参数
- [[linux/防火墙/nftables.md|nftables]] — 内核实际执行框架，table/chain/set，常用命令
- [[linux/防火墙/firewalld.md|firewalld]] — RHEL 系，zone 管理
- [[linux/防火墙/ufw.md|ufw]] — Debian 系，allow/deny + app profile

## 2. 四者关系一句话总结

|工具|定位|
|---|---|
|nftables|内核实际执行的框架（2026年主流发行版底层都是它）|
|iptables|旧命令语法，翻译成 nftables 规则执行（兼容层）|
|firewalld|RHEL系动态管理层，概念是 zone，管的是 iptables/nftables|
|ufw|Debian系简化命令行，概念是 allow/deny + app profile，管的也是 iptables/nftables|

## 3. 与云安全组的关系

||安全组|iptables/firewalld|
|---|---|---|
|工作层|VPC 网络层（流量到达主机前）|操作系统内核层|
|规则顺序|无序，并行评估|**有序，从上到下匹配**|
|NAT 能力|无|有|
|状态追踪|自动处理|需手动配置|

生产环境两层都配：安全组做粗粒度过滤，主机防火墙做细粒度控制。

## 4. 学习优先级（SRE/运维方向）

1. **iptables 模型**（链、表、匹配、动作、顺序）— 必须理解，排障基础
2. **firewalld/ufw** — 会基本操作即可
3. **nftables 语法** — 有余力了解
4. **eBPF/Cilium** — K8s 方向的趋势

## 5. 排障时怎么用

怀疑防火墙拦截时，别直接改规则，先用计数器确认（如 `iptables -L -n -v` 看 packets 有没有增长），完整判断路径见 [[linux/网络排障/网络故障排查 Runbook.md]]。
