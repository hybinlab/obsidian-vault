## 🔒 安全头部 (Security Headers)

**HTTP 安全头部**通过提供针对**跨站脚本 (XSS)**、**点击劫持 (clickjacking)** 等攻击的缓解措施，有助于提高 Web 应用程序的整体安全性。我们现在将深入探讨以下安全头部：

* **Content-Security-Policy (CSP)** (内容安全策略)
* **Strict-Transport-Security (HSTS)** (严格传输安全)
* **X-Content-Type-Options** (X-内容类型选项)
* **Referrer-Policy** (引用者策略)

您可以使用像 `**https://securityheaders.io/**` 这样的网站来分析任何网站的安全头部。在完成本任务的讨论后，您有望更好地理解该网站报告的内容。


-----

### Content-Security-Policy (CSP) (内容安全策略)

**CSP** 头部是额外的安全层，可以帮助缓解像跨站脚本 (XSS) 这样的常见攻击。恶意代码可能托管在单独的网站或域上，并被注入到易受攻击的网站中。 **CSP** 为管理员提供了一种方法来声明哪些域或来源是安全的，从而为这类攻击提供了一层缓解措施。

在头部本身中，您可能会看到定义了 `**default-src**` 或 `**script-src**` 等属性，以及更多其他属性。这些都为管理员提供了在各种粒度级别上定义哪种类型的内容允许从哪些域加载的选项。使用 `**self**` 是一个特殊的关键词，它指代托管该网站的同一域。

查看一个 **CSP** 头部示例：

```
Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.tryhackme.com; style-src 'self'
```

我们看到使用了：

* `**default-src**`：指定了默认策略为 `**self**`，意味着**只允许来自当前网站**的内容。
* `**script-src**`：指定了脚本可以从何处加载的策略，即 `**self**` 以及托管在 `**https://cdn.tryhackme.com**` 上的脚本。
* `**style-src**`：指定了 CSS 样式表可以从**当前网站 (**`**self**`**)** 加载的策略。


-----

### Strict-Transport-Security (HSTS) (严格传输安全)

**HSTS** 头部确保 Web 浏览器将**始终通过 HTTPS 连接**。我们来看一个 HSTS 的示例：

```
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
```

以下是示例 HSTS 头部按指令进行的细分：

* `**max-age**`：这是此设置的**过期时间**（以秒为单位）。
* `**includeSubDomains**`：这是一个**可选设置**，指示浏览器也将此设置应用于所有**子域**。
* `**preload**`：这是一个**可选设置**，允许网站被包含在预加载列表中。浏览器可以使用预加载列表，在用户首次访问网站之前就**强制执行 HSTS**。


-----

### X-Content-Type-Options (X-内容类型选项)

`**X-Content-Type-Options**` 头部可用于指示浏览器**不要猜测**资源的 **MIME** 类型，而**只使用** `**Content-Type**` **头部**。这是一个示例：

```
X-Content-Type-Options: nosniff
```

以下是 `X-Content-Type-Options` 头部按指令进行的细分：

* `**nosniff**`：此指令指示浏览器**不要嗅探**或猜测 **MIME** 类型。


-----

### Referrer-Policy (引用者策略)

当用户从源 Web 服务器重定向到目标 Web 服务器时（例如，当他们点击超链接时），此头部控制发送给目标 Web 服务器的**信息量**。该头部可供 Web 管理员控制共享哪些信息。以下是 **Referrer-Policy** 的一些示例：

```
Referrer-Policy: no-referrer
Referrer-Policy: same-origin
Referrer-Policy: strict-origin
Referrer-Policy: strict-origin-when-cross-origin
```

以下是 **Referrer-Policy** 头部按指令进行的细分：

* `**no-referrer**`：这**完全禁用**发送任何关于引用者的信息。
* `**same-origin**`：此策略**仅在目的地属于同一来源时**发送引用者信息。当您希望在超链接位于同一网站内时传递引用者信息，但不希望传递给外部网站时，这很有帮助。
* `**strict-origin**`：此策略**仅在协议保持不变时**发送引用者作为来源 (origin)。因此，当 HTTPS 连接跳转到另一个 HTTPS 连接时，会发送引用者。
* `**strict-origin-when-cross-origin**`：这与 `strict-origin` 类似，但对于**同一来源**的请求，它会在引用者头部中发送完整的 URL 路径。
