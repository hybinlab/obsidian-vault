- [x] **Caddy（反向代理）** —— ✅ 已定案并部署（2026-08-24，docker-host）「反代三选一」尘埃落定
  - 仓库：https://github.com/caddyserver/caddy（75k stars）
  - 文档：https://caddyserver.com/docs/
  - 定位：Go 写的 HTTP/1-2-3 server，**自动 HTTPS**（Let's Encrypt 自动签/续期，证书零管理）；Caddyfile 极简配置
  - 学习价值：最省心地给服务挂域名+TLS；正对"无痛 HTTPS"痛点；**文本声明式配置** vs Traefik(YAML/标签)/NPM(点界面)

  - 配置要点：Caddyfile 用 `tls { dns alidns { access_key_id {env.ALIYUN_ACCESS_KEY_ID} access_key_secret {env.ALIYUN_ACCESS_KEY_SECRET} } }`；**变量名是 `ALIYUN_ACCESS_KEY_ID/SECRET`**（不是 lego 的 `ALICLOUD_*`，踩过坑）；凭据明文在 compose 里，**待建 RAM 子账号限 DNS 权限替换**
  - 已挂载站点：`vault.onecloud.xin`→8084(vaultwarden)、`code.onecloud.xin`→8080(code-server)、`karakeep.onecloud.xin`→3002(karakeep)
  - **DNS 排障（关键坑）**：OpenClash fake-ip 全量劫持 53 + Clash 过滤私有 IP → 内网 A 记录空应答。正解=网关 OpenWrt 的 dnsmasq `/etc/hosts` 逐条写内网域名→内网IP（勿通配），不经 OpenClash。记录见本机 `~/knowledge-poc-vaultwarden-internal-https.md`
