## 运算符分类

| 类别 | 运算符 | 说明 |
| --- | --- | --- |
| 算术 | `+` `-` `*` `/` `%` `^` | 数值计算 |
| 字符串 | `+` | 拼接两个字符串，或字符串和 Secret 混拼 |
| 比较 | `==` `!=` `<` `<=` `>` `>=` | `==`/`!=` 任意类型都能比；序比较（`<` 等）要求两边类型相同且可排序 |
| 逻辑 | `&&` `||` `!` | 布尔值组合，返回布尔结果 |
| 赋值 | `=` | Attribute 赋值，支持有效范围内的隐式类型转换（数字↔字符串） |
| 访问 | `[]` `.` | 数组/对象索引、组件导出访问 |

优先级遵循标准数学的 **PEMDAS**（括号 → 幂 → 乘除 → 加减），逻辑/比较运算符按常规惯例排在算术之后；具体每一档的运算符归属官方文档没有给出详细表格，写复杂表达式时不确定优先级就直接加括号，不用去猜。

## 算术 + 字符串拼接

`+` 同时身兼算术加法和字符串拼接两种含义，靠操作数类型区分：

```alloy
prometheus.scrape "app" {
  targets = [{ "__address__" = local.file.host.content + ":" + local.file.port.content }]
}
```

这里 `host.content` 和 `port.content` 都是字符串，`+` 就是拼接，拼出 `"host:port"` 这样的 target 地址。

## 比较运算符

`==`/`!=` 可以跨任意类型比较（类型不同直接判 false，不会报错）；`<`/`<=`/`>`/`>=` 只能用在同类型且"可排序"的值上——数值按大小排，字符串按字节的字典序排。

常见写法是用比较结果直接当布尔值用：

```alloy
remote_write_enabled = sys.env("ENVIRONMENT") == "production"
```

## 访问运算符：`[]` 和 `.`

- `.` 用来访问组件导出、对象里语法合法的固定字段，访问不存在的字段会**报错**
- `[]` 用来按下标/key 动态访问数组/对象，访问不存在的对象成员会返回 **`null`**（不报错），这个区别在写容错逻辑时很关键——想要"不存在就给默认值"的效果，得用 `[]` 而不是 `.`

两种访问运算符可以嵌套/混用，还能接着做拼接：

```alloy
prometheus.scrape "dynamic" {
  targets  = discovery.kubernetes.endpoints.targets
  job_name = discovery.kubernetes.endpoints.targets[0]["job"] + "-scraper"
}
```

这行先用 `.targets` 拿到组件导出的数组，再用 `[0]` 取第一个元素，再用 `["job"]` 取这个 object 里的 `job` 字段，最后拼上字符串后缀。

## 三种括号的分工

- `()` 圆括号：改变运算优先级，跟数学里一样
- `{}` 花括号：定义 Block 或 Object 字面量
- `[]` 方括号：定义 Array 字面量，或者做索引访问

## 小结

日常写 Alloy 配置里用运算符最多的场景就是两个：拼字符串（`+` 拼 host:port、拼 job_name 后缀）、拼条件判断（`==` 判断环境变量决定要不要启用某个组件）。`.` 和 `[]` 的报错行为差异（报错 vs 返回 null）是唯一需要刻意记住的坑。
