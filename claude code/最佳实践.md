# 最佳实践

## 🛠️ Claude Code 核心工作流 SOP

### 1. 战前准备：拉起护栏

在项目根目录（或前后端子目录）下，必须维持一个最新、清晰的 `CLAUDE.md` 文件。

* **做法**：里面固化团队的**死规则**（例如：技术栈、Lint 规范、测试框架、核心设计模式）。
* **目的**：每次启动 CC 时，它会自动读取此文件作为基调，防止 AI 给你写出不符合团队规范的野路子代码。

### 2. 复杂任务：先规划，后动手

面对大需求、重构或复杂 Bug 修复，**严禁**让 AI 直接开干。

* **第一步：建立检查清单（**`**TODO.md**`**）** 让 CC 扫描代码并把任务拆解写入 `TODO.md`。例如： `> 将需要修复的 lint 错误写入 TODO.md 作为检查清单`
* **第二步：沙盒演练（**`**SCRATCH.md**`**）** 创建一个临时的 Markdown 方案草稿本。 `> 创建 SCRATCH.md，在里面规划 API 重构方案` 在这里和 CC 反复对齐方案、补充边界条件，确保思路 100% 正确。**此过程不污染一行生产代码。**

### 3. 战术执行：高频跑通测试（TDD 节奏）

进入编写阶段后，严格执行"小步快跑，逐个击破"：

* **分步确认**：使用 `/plan` 模式或根据 `TODO.md` 逐个处理。AI 冲锋一步（例如修改完一个 API 接口），立刻要求其停下，由你作为审查者（Director）进行 Review。
* **测试门禁**：每改完一个点，立刻命令 CC 运行本地测试： `> 运行测试确认覆盖率` 只有终端刷出绿灯（`PASS`），才允许推进到下一个 TODO。

### 4. 战术悬崖勒马：善用 `Escape` 键

一旦发现 CC 领会错了意图，或者生成的 Diff 开始疯狂偏离轨道：

* **做法**：**立刻按下** `**Escape**` **键强行打断**。
* **收敛**：中断后，立刻口头纠正并将其固化，防止它再次犯错： `> 记住：这个项目使用 Tailwind CSS，不要用行内样式` `> 把这条规则添加到 CLAUDE.md`

### 5. 战后清理：定期战略压缩

密集的对话会迅速让上下文变脏、变重（浪费 Token 且让 AI 变蠢）。

* **做法**：当一个阶段（如"调研 $\rightarrow$ 编码"）结束，准备进入下一阶段（如"重构 $\rightarrow$ 验证"）时，及时使用 `/clear` 或 `/compact` 彻底清理/压缩一次会话上下文，重新轻装上阵。


---

> 💡 **一句话总结这套 Vibe Coding 实践**： **人类退居二线充当"架构师 + 质检员"**（管住 `CLAUDE.md` / `TODO.md`，手握 `Escape` 刹车和 `Test` 门禁），\*\*让 CC 充当"顶尖且不知疲倦的码农"\*\*去疯狂执行。在这种高频且正确的正反馈中，开发效率和多巴胺自然就全部拉满了。
