## 恢复会话

会话按项目目录保存在本地，退出或 `/clear` 之后都能找回来。

| 命令 | 作用 |
| --- | --- |
| `claude --continue` / `-c` | 打开当前目录最近一次对话 |
| `claude --resume` / `-r` | 打开会话选择器 |
| `claude --resume <名字或ID>` | 直接恢复指定会话（ID 可以在任意目录下恢复） |
| `/resume` | 在会话内切换到另一个对话 |
| `claude -n <名字>` | 启动时就给会话命名 |

会话选择器里的按键：`Space` 预览，`Ctrl+R` 重命名，`/` 搜索，`Ctrl+A` 显示所有项目的会话，`Ctrl+B` 只看当前分支。

注意：

- `claude -p` 产生的会话不会出现在选择器和 `--continue` 里，只能用 ID 恢复。
- 恢复时**不会**恢复启动参数 `--mcp-config`、`--settings`、`--add-dir` 等，需要重新传。
- 一个闲置超过约 1 小时、超过 10 万 token 的会话，恢复时会问你是**从摘要恢复**（更省）还是**完整恢复**。

**命名的建议**：用 `/rename oauth-migration` 给会话起有意义的名字，把每条工作线当成一个"分支"，以后用 `claude --resume oauth-migration` 直接回来。

## 分支

想试另一条思路又不想丢掉当前进度：

```text
/branch try-streaming-approach
```

或在命令行运行 `claude --continue --fork-session`。原对话保持不变，可以用 `/resume` 回去。

## Checkpoint 与回滚

- 你每发一条开启新回合的消息，就会自动创建一个 checkpoint，记录 Claude **通过编辑工具**改过的文件。
- `Esc` `Esc`（输入为空时）或 `/rewind` 打开回滚菜单，选一个历史消息后可以：
  - **Restore code and conversation**：代码和对话都回到那个时刻
  - **Restore conversation**：只回滚对话，保留当前代码
  - **Restore code**：只回滚文件，保留对话
  - **Summarize from here / up to here**：把这之后/之前的对话压缩成摘要（局部的 `/compact`）
- checkpoint 随会话保存，关掉终端再 resume 也能回滚。

**局限（重要）**：

- Bash 命令造成的改动（`rm`、`mv`、`cp`…）**不会被跟踪**；
- 大部分子代理的编辑不会被回滚；
- 你在外部手动改的文件不跟踪；
- **不能替代 git**。

所以可以放心让 Claude "大胆试一下"，不行就 rewind，但关键节点还是要提交。

## 管理上下文

| 手段 | 用法 |
| --- | --- |
| `/clear` | 无关任务之间清空上下文。**同一问题纠正两次还不对，就 clear 后重写提示词** |
| `/compact <重点>` | 手动压缩，如 `/compact 重点保留 API 改动` |
| 自动压缩 | 接近上限时自动触发；`/autocompact` 可以调整触发阈值 |
| `/btw <问题>` | 问个小问题，答案不进历史 |
| 子代理 | "use subagents to investigate X"，调研过程不占主上下文 |
| 局部摘要 | rewind 菜单里的 Summarize |

在 CLAUDE.md 里可以写压缩时要保留什么，例如 "When compacting, always preserve the full list of modified files and any test commands"。

## 常见失败模式

| 现象 | 解决 |
| --- | --- |
| 一个会话里东一个西一个任务（kitchen sink） | 任务之间 `/clear` |
| 反复纠正同一个错误 | 纠正两次失败后 `/clear`，带着经验重写提示词 |
| CLAUDE.md 太长，规则被忽略 | 精简；能用 hook 强制的就改成 hook |
| 看起来对但没处理边界情况 | 一定要给验证手段（测试/脚本/截图） |
| "调查一下" 没有范围，读了几百个文件 | 缩小范围，或交给子代理 |

## 写提示词的技巧

- **给出验证标准**："写一个 validateEmail 函数，测试用例：…，实现后运行测试"。
- **指明来源**："看 ExecutionFactory 的 git 历史，总结它的 API 是怎么演变来的"。
- **引用已有模式**："参考首页现有 widget 的实现方式，HotDogWidget.php 是个好例子"。
- **描述症状**：现象 + 大概位置 + "修好"的标准。
- 用 `@文件` 引用文件、直接粘贴截图，或通过管道输入：`cat error.log | claude -p "解释这个错误"`。
- 大功能先让 Claude 采访你："Interview me in detail using the AskUserQuestion tool… 然后写成 SPEC.md"，再**开一个新会话**按 spec 实现。
