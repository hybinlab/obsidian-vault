## 非交互模式 `claude -p`

用于脚本、CI、管道：

```bash
# 一次性提问
claude -p "Explain what this project does"

# 管道输入
cat build-error.txt | claude -p '简要解释这个构建错误的根因' > output.txt

# JSON 输出，用 jq 取结果
claude -p "Summarize this project" --output-format json | jq -r '.result'

# 按 JSON Schema 输出结构化数据
claude -p "Extract the main function names from auth.py" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}'

# 流式输出
claude -p "Analyze this log" --output-format stream-json --verbose
```

权限相关：

```bash
# 预先放行指定工具
claude -p "Run the test suite and fix any failures" --allowedTools "Bash,Read,Edit"

# 只允许看 diff 和提交
claude -p "Look at my staged changes and create an appropriate commit" \
  --allowedTools "Bash(git diff *),Bash(git log *),Bash(git status *),Bash(git commit *)"

# CI：只允许白名单，其他一律拒绝
claude -p "run the test suite" --permission-mode dontAsk --allowedTools "Bash(npm test)" "Read"
```

- `--bare`：跳过 hooks、skills、MCP、CLAUDE.md 等的自动发现，启动更快，**推荐在脚本里用**。注意：不加 `--bare` 时，`-p` 会在未信任的目录里也执行项目的 hooks 和 MCP。
- `--append-system-prompt`：在默认系统提示词后面追加指令。
- `--output-format json` 的结果里有 `total_cost_usd`，可以用来统计花费。
- 批量处理：先让 Claude 生成待处理文件列表，然后用循环调用 `claude -p`，先拿 2～3 个文件试，再全量跑。

## 后台会话与 Agent view

`claude` 直接启动的会话绑定在终端上，终端一关就结束。**后台会话**由一个 supervisor 进程托管，关掉终端也会继续运行。

```bash
claude --bg "investigate the flaky test"                 # 直接在后台启动一个任务
claude --bg --name "flaky-fix" "..."                     # 带名字
claude --agent code-reviewer --bg "review PR 1234"       # 用指定子代理
claude --bg --exec 'pytest -x'                           # 后台跑一个 shell 命令（不调用模型）

claude agents          # 打开 agent view，查看所有后台会话
claude attach <id>     # 接入某个会话
claude logs <id>       # 查看最近输出
claude stop <id>       # 停止
```

会话内：

- `/bg`（或 `/background`）：把当前会话移到后台，释放终端；
- 空输入时按 `←`：移到后台并打开 agent view；
- `/fork`：复制当前对话到一个新的后台会话，自己继续在原会话工作。

Agent view 里：`Space` 预览并回复，`Enter` / `→` 接入，空输入时 `←` 退出，`Ctrl+T` 固定会话（防止空闲一小时后进程被回收）。

注意：

- 每个后台会话都**独立消耗额度**；
- 会话跑在本机，**关机就停**（休眠后可以恢复）；
- 目前是 research preview 阶段。

> 关于"关掉终端后在手机上继续"，见 [[Remote Control 手机远程接管会话]]。

## 定时与持续执行

| 方式 | 何时开始下一轮 | 何时停止 |
| --- | --- | --- |
| `/loop [间隔] [提示词]` | 时间到了 | 你停止它，或 Claude 判断已完成 |
| `/goal <条件>` | 上一轮结束 | 另一个模型判断条件已满足 |
| Stop hook | 上一轮结束 | 你的脚本决定 |

```text
/loop 5m check if the deployment finished and tell me what happened
/loop check whether CI passed and address any review comments   # 不写间隔，由 Claude 自己决定
/goal all tests in test/auth pass and the lint step is clean
```

- `/loop` 是会话级别的：会话关了就停，最小间隔 1 分钟，7 天后过期。
- `/goal` 的条件要写成**可以从对话输出里验证**的形式（测试结果、退出码、`git status` 干净），因为评估器不会自己去跑命令。想让它无人值守地跑，需要配合 auto 模式。
- 不依赖本机、长期运行的定时任务，用云端 **Routines**（`/schedule`），最小间隔 1 小时。

## Worktree 并行

```bash
claude --worktree feature-auth   # 或 -w；在 .claude/worktrees/feature-auth/ 新建分支 worktree-feature-auth
```

- 每个会话一个 worktree，改动互不干扰；
- 把 `.claude/worktrees/` 加进 `.gitignore`；
- 退出时，如果 worktree 没有改动，会自动清理；
- 会话中也可以直接说"work in a worktree"。

**Writer / Reviewer 模式**：会话 A 负责实现，会话 B 在干净的上下文里审查 A 的代码（不会偏袒自己写的代码），再把审查意见交回 A 修改。
